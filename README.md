# 포카바인더 얼굴 인식 프로토타입

포토카드 이미지를 입력받아 얼굴을 검출하고, 얼굴 특징을 바탕으로 아티스트·멤버 후보를 찾은 뒤 자동 승인·관리자 검수·반려로 분기하는 웹 프로토타입입니다. 화면에서 보여 주는 전체 서비스 흐름과 실제로 구현된 인식 엔진의 범위는 다르므로 아래의 구현 범위를 함께 확인해야 합니다.

## 페이지 구성

- [index.html](./index.html): 서비스 소개용 랜딩 페이지
- [prototype.html](./prototype.html): 클릭형 화면 흐름과 실제 얼굴 인식 엔진을 포함한 인공지능 프로토타입
- [ai-report.html](./ai-report.html): 제한된 평가 자료로 만든 별도 인공지능 평가 리포트

## 로컬 실행

저장소 루트에서 다음 명령을 실행합니다.

```bash
python3 -m http.server 8765
```

브라우저에서 다음 주소로 접속할 수 있습니다.

- 랜딩: <http://localhost:8765/index.html>
- 프로토타입: <http://localhost:8765/prototype.html>
- 평가 리포트: <http://localhost:8765/ai-report.html>

`file://`로 파일을 직접 열면 모델과 인덱스를 가져오는 `fetch`가 동작하지 않으므로 반드시 HTTP 서버를 통해 실행해야 합니다.

최초 실제 분석 시 약 65MB를 내려받으므로 네트워크 상태를 확인하고, 최신 WebAssembly를 지원하는 브라우저 사용을 권장합니다.

## 배포 프로토타입 처리 파이프라인

1. SCRFD `det_10g` int8 모델로 얼굴과 5점 랜드마크를 검출합니다.
2. ArcFace `w600k_r50` 모델로 512차원 임베딩을 만들고, 코사인 유사도로 아티스트·멤버 후보를 매칭합니다.
3. 선명도, 밝기, 얼굴 크기를 바탕으로 기본 이미지 품질을 계산합니다.
4. 아래 고정 임계값으로 결과를 분기합니다.

   - `simAuto` 0.44 이상이면서 `gapAuto` 0.05 이상: 자동 승인
   - `simReview` 0.33 이상: 관리자 검수
   - 0.33 미만: 반려

이 임계값은 현재 배포 프로토타입의 동작 기준이므로 임의로 변경하지 않습니다.

## 인덱스와 평가 범위

- 웹 배포 인덱스: 6,106명, 6,244개 벡터
- 평가 리포트 인덱스: 63명, 138개 벡터
- 리포트 평가 자료: 이미지 70장

두 인덱스의 규모와 구성이 다릅니다. 따라서 [ai-report.html](./ai-report.html)의 결과는 제한된 별도 평가 결과이며, 웹 배포 엔진의 성능을 보증하지 않습니다.

## `prototype.html`·`pocaai.js` 브라우저 엔진 구현 범위

[prototype.html](./prototype.html)에서 [pocaai.js](./pocaai.js)가 실행하는 브라우저 인식 엔진을 기준으로 실제 구현된 기능은 다음과 같습니다.

- 얼굴 검출
- 얼굴 기반 아티스트·멤버 후보 매칭
- 선명도·밝기·얼굴 크기에 기반한 기본 이미지 품질 계산
- 자동 승인·관리자 검수·반려 분기

다음 기능은 이 브라우저 엔진에 구현되지 않았습니다.

- 광학 문자 인식(OCR)
- 카드 중복 검색
- 앨범·유형·버전 메타데이터 연동

화면에는 향후 서비스의 흐름을 설명하기 위한 시연 요소가 포함될 수 있습니다. 이를 위의 실제 엔진 구현 범위와 구분해서 해석해야 합니다.

[ai-report.html](./ai-report.html)은 브라우저 엔진과 별개인 정적 평가 산출물입니다. 카드 중복 검색 결과가 표시되어 있어도 해당 기능이 브라우저 엔진에 구현되었다는 뜻은 아닙니다. 저장소에는 리포트 평가 재현 코드와 샘플 목록이 포함되어 있지 않습니다.

## 모델 출처와 라이선스

파일명과 [model_parts.json](./model_parts.json)의 분할 명세는 InsightFace `buffalo_l` 구성의 `det_10g`, `w600k_r50`에서 파생된 int8 양자화 모델임을 시사합니다. 다만 변환 스크립트가 없고 변환 과정과 원본 해시는 이 저장소에 기록되어 있지 않습니다. 정확한 변환 출처는 배포 전에 별도로 확인해야 합니다.

**InsightFace 사전학습 모델은 비상업 연구용 라이선스이며 상용 적용 전 별도 라이선스 확인 필요**

[ort.wasm.min.js](./ort.wasm.min.js) 헤더에는 `ONNX Runtime Web v1.27.0`과 `MIT License`가 명시되어 있습니다. 배포 시 해당 상위 프로젝트의 저작권·허가 고지를 `LICENSE` 또는 `NOTICE` 형태로 보존해야 합니다. 이는 포함된 런타임 구성요소에 관한 안내이며, 프로젝트 전체 라이선스를 선언하는 내용이 아닙니다.

## 알려진 제한

- 얼굴이 없는 사진은 320·640 두 입력 크기에서 패딩 3단계를 모두 시도하므로 최대 6회 검출합니다. 단일 스레드 WebAssembly 환경에서는 30초 이상 걸릴 수 있으며, Chromium 검증에서는 빈 400×600 이미지가 36.5초 걸렸습니다. 실제 시간은 기기와 브라우저에 따라 달라집니다.
- 검출 모델이 640 입력 기준으로 내보내져 320 입력에서는 ORT가 `VerifyOutputSizes` 경고를 콘솔에 표시할 수 있습니다. Chromium 검증에서는 이 경고가 있어도 320 입력 추론은 정상 동작했습니다.
- 사진에 얼굴이 여러 개 있어도 브라우저 엔진은 검출 면적이 가장 큰 얼굴 1개만 최종 판정합니다.

## 분할 파일 운영

인식 ONNX 모델과 ONNX Runtime(ORT) 웹어셈블리 파일은 저장소 및 호스팅의 업로드 제약 때문에 `.partN` 파일로 분할되어 있으며, 브라우저가 실행 시 이를 조립합니다.

- 얼굴 검출 모델: [det_10g_int8.onnx](./det_10g_int8.onnx)
- 분할된 얼굴 인식 모델: `w600k_r50_int8.onnx.partN`
- 분할된 ORT 웹어셈블리: `ort-wasm-simd-threaded.wasm.partN`
- 분할 명세: [model_parts.json](./model_parts.json)
  - 인식 모델 항목에는 SHA-256과 크기 정보가 있습니다. `pocaai.js`는 조립 후 크기와 SHA-256을 검증합니다.
  - WASM 항목에는 크기 정보가 있고 SHA-256은 없습니다. 현재 `prototype.html` 로더는 조립한 WASM의 총 크기를 검사합니다.

현재 로더는 기본적으로 상대 경로를 사용합니다. 인식 모델과 관련 파일은 `baseUrl`을 기준으로, WASM 조각은 문서의 기준 주소(`document.baseURI`)를 기준으로 찾습니다.

운영 환경에서는 대용량 파일을 GitHub Release 자산 또는 CDN으로 이전하는 방식을 권장합니다. 이전할 때는 인식 로더의 `baseUrl`, WASM과 매니페스트 경로 설정, 원격 호스트의 CORS 허용을 함께 변경해야 합니다. 또한 버전 경로를 사용해 캐시를 무효화하고, 파일 변경 시 인식 모델의 SHA-256을 갱신하며, 모델·런타임 버전을 함께 관리해야 합니다.
